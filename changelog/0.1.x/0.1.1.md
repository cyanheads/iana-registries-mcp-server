# 0.1.1 — 2026-10-01

## Added

- **`iana_lookup_port`** — service name and port assignments by `port` (0–65535), exact `service`, or `keyword`, filterable by `transport`; each transport is listed separately, an unassigned port reports its range row, and every port is classed System, User, or Dynamic/Private.
- **`iana_lookup_media_type`** — media types by exact `type` or `keyword`, filterable by `top_level`; an exact lookup also reads the registration template for its file-extension, intended-usage, and deprecated-alias statements, and a deprecated type names its replacement.
- **`iana_lookup_http_status`** — HTTP status codes by `code` (100–599) or reason-phrase `keyword`: phrase, class, defining reference with section, and temporary, obsoleted, or unused state; an unassigned code returns `found: false` with its unassigned range.
- **`iana_lookup_http_field`** — HTTP field names by case-insensitive `name` or `keyword`, filterable by `status`: registration status (permanent, provisional, deprecated, obsoleted), Structured Field type, and defining reference.
- **`iana_lookup_uri_scheme`** — URI schemes by `scheme` (a trailing `:` or `://` is ignored) or `keyword`, filterable by `status`: status, description, references, and well-known URI support.
- **`iana_lookup_pen`** — Private Enterprise Numbers by `pen` (a number, or an OID under `1.3.6.1.4.1`) or `organization`: the organization and its OID prefix.
- **`iana_lookup_language_tag`** — validates a BCP 47 `tag` subtag by subtag against the Language Subtag Registry, reporting preferred values for deprecated subtags and the canonical form of a valid tag, or searches subtags by `description`, filterable by `subtag_type`.
- **`iana_get_rfc_status`** — up to 10 RFCs or Internet-Drafts per call: RFC current and as-published status, obsoletes/updates relations, and errata; draft state, IESG state, expiry, and replacement. Ids that would exceed the call's 20 Datatracker requests return in `failed` with `request_limit`.
- **`iana_search_registries`** — finds registries and sub-registries in the IANA protocol index by words in their titles, categories, and ids, returning the ids `iana_get_registry_records` reads, the registration procedure, and the defining documents.
- **`iana_get_registry_records`** — reads any IANA XML registry by id or `iana.org/assignments` URL, with `subregistry`, an exact `value` filter on the key column (a decimal also matches range rows), `contains`, and `cursor` paging; field names are the registry's XML element names.
- **Lookup contract** — each lookup takes exactly one mode key and fails `mode_required` otherwise; a miss returns `found: false` with a notice instead of an error, and list modes page with `offset` and `next_offset`.
- **Service boundary** — reads only iana.org, rfc-editor.org, and datatracker.ietf.org, over https with redirects held to those hosts, under per-host pacing, per-body byte ceilings, and one 45-second budget per tool call; a full queue fails `pacer_shed` with `retryAfter`.
- **Registry cache** — each registry loads on first use and stays fresh for 24 hours; when a refresh fails, a copy up to 7 days old answers with `source.stale: true`. Every registry response's `source` carries the registry's own `registry_updated` date.
- **Config** — no API keys and no server-specific environment variables; HTTP sessions default to stateless, and the framework's transport, auth, and logging settings apply as usual.
- **Person data** — registry contacts, designated experts, assignees, and person references are dropped at parse, as are Datatracker author emails and affiliations; email addresses in free text become `[email removed]`, and a PEN organization line holding an address is withheld.
- **Data terms** — IANA registry data is CC0 1.0 under the IANA/IETF Trust licensing terms; RFC metadata comes from the RFC Editor and the IETF Datatracker, and RFC text is never returned.

## Dependencies

- `fast-xml-parser` ^5.11.1 added for registry XML parsing; built on `@cyanheads/mcp-ts-core` ^0.13.10.
